# GODIEOR persistent Linux batch runner

These units are for a **real Linux host with persistent storage**, not Render Free web service. Run from a checkout at `/opt/godieor/backend` with Node.js 24 and `npm ci && npm run build` completed. The `godieor` Unix user must own the checkout's ignored `work/` tree and be able to update `data/curated/ott-reviewed-mappings.json`. Preserve the existing reviewed `work/ott-candidates/state.json`, other review state and mapping files when transferring from the Mac; do not start OTT on a blank directory. Transfer only after checking these files for credentials or other sensitive information, through an authenticated channel controlled by the owner.

Keep credentials in `/etc/godieor/collection.env` mode 0600, readable by the systemd service user, with `DATABASE_URL` set to the **cloud PostgreSQL** URI. Include `CURSOR_SIGNING_KEY`, `KOBIS_API_KEY`, `FOOTBALL_DATA_API_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `TMDB_API_READ_ACCESS_TOKEN`, plus `COLLECTION_INCLUDE_FIXTURE=false`, `COLLECTION_SCHEDULE_ENABLED=false`. Never commit this file. Existing OTT subprocesses require a local `.env` file even when all values come from environment; create an **empty** file with mode 0600 inside the backend checkout.

Install the four unit files into `/etc/systemd/system`, then run `sudo systemctl daemon-reload`, `sudo systemctl enable --now godieor-provider.timer godieor-ott.timer`. Validate the units and next triggers with `systemctl list-timers 'godieor-*'`; trigger each service once using `sudo systemctl start godieor-provider.service` and `sudo systemctl start godieor-ott.service`. Inspect `systemctl status` and `journalctl -u godieor-provider.service -u godieor-ott.service`, and compare `work/*-last-run.json` and cloud DB rows with the expected sources. OTT exit code 2 means **partial discovery** and must not be reported as full success. Do not enable both the GitHub provider cron and this timer against the same DB. Only unload the two Mac LaunchAgents **after remote scheduling and successful run are confirmed**.

The user-selected API hosting is Render Free + Supabase Free. Render Free web does not guarantee an always-on process or persistent writable filesystem, so these units need a separate always-on Linux host (such as a prepared SOYO mini PC). This repository does not contain verified SSH access to that host or Supabase/Render credentials.
