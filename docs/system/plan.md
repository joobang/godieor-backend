## 작업 목표와 완료 단위

작품 한 건의 적재를 ‘다음 작업 완료’ 단위로 반복하지 않는다. 사용자에게 보이는 기능/결함 묶음으로 설계·재현·수정·검사를 끝낸다. 최신 사용자 지시로 OTT 참조 누락 해소를 최우선으로 진행한다. 신작·시즌 첫 공개를 원인별 묶음으로 대조·수정·게시하며 회차 확장은 제외한다. 기존 앱 흐름 작업은 이 우선순위 뒤에 둔다.

## 데이터 작업의 종료 조건

기존 CLI는 이미 전체 매핑을 배치 입력으로 처리한다. 부족했던 것은 개별 작품 발견을 작업 종료로 반복한 운영 방식이다. 새 공통 원천이나 날짜 증거가 없으면 같은 페이지를 다시 찾지 않는다. 실패 이유와 재개 조건을 한 백로그에 남긴다. 근거가 준비된 전체 묶음의 국가·플랫폼·공개 방식·정밀도를 검토해 한 번에 처리한다. 전체 국가를 아우르는 DB 원자성은 기존 구현에서 보장하지 않으며 scope별 결과와 재실행을 확인한다.

## 기록과 실제 상태

제품 수정은 BE-AUTH-07/APP-AUTH-13 뒤 사용자 우선순위에 따라 DATA-53을 진행했다. 실제 로컬 11~12월KR4OTT67행/연중69매핑이며 최신제품일치26/52, TMDB후보발견49/52다. 후보와 게시를 구분한다. 단순 건수 충족과 참조 항목 일치를 구분한다. 작업 기록은 해당 원본 카드 하나에 모으고 공통 문서는 상태/다음 행동만 요약한다. 자체검사·unsigned 빌드·폰 관찰·독립 승인은 구분한다. 승인 기준 원본은 verifier이며 실폰/외부리뷰 없는 전체제품PASS를 선언하지 않는다.
