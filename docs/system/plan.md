## 작업 목표와 완료 단위

작품 한 건의 적재를 ‘다음 작업 완료’ 단위로 반복하지 않는다. 사용자에게 보이는 기능/결함 묶음으로 설계·재현·수정·검사를 끝낸다. 데이터 적재는 제품 개발의 선행 조건으로 계속 확장하지 않는다. 현재 가진 데이터로 핵심 흐름부터 검증한다.

## 데이터 작업의 종료 조건

기존 CLI는 이미 전체 매핑을 배치 입력으로 처리한다. 부족했던 것은 개별 작품 발견을 작업 종료로 반복한 운영 방식이다. 새 공통 원천이나 날짜 증거가 없으면 같은 페이지를 다시 찾지 않는다. 실패 이유와 재개 조건을 한 백로그에 남긴다. 근거가 준비된 전체 묶음의 국가·플랫폼·공개 방식·정밀도를 검토해 한 번에 처리한다. 전체 국가를 아우르는 DB 원자성은 기존 구현에서 보장하지 않으며 scope별 결과와 재실행을 확인한다.

## 기록과 실제 상태

제품 수정은 BE-AUTH-07 다음 APP-AUTH-13까지 진행했다. 데이터는 추가하지 않았으며 DATA-52의 기간63건/연중65매핑은 과거 마지막 관측으로 남긴다. 작업 기록은 해당 원본 카드 하나에 모으고 공통 문서는 상태/다음 행동만 요약한다. 자체검사·unsigned 빌드·폰 관찰·독립 승인은 구분한다. 승인 기준 원본은 verifier이며 실폰/외부리뷰 없는 전체제품PASS를 선언하지 않는다.
