# OTT 최초 공개일 확보 가능성 · DATA-01

확인: 2026-11-09 KST. 구현 담당의 공개 문서/HTTP 접근 조사다. 제품 연동·독립 검증·전수 정확성 검사가 아니다.

## 결론과 판단 범위

무료 API 하나로 네 OTT의 한국·시즌별 최초 공개일을 전수 확보할 근거는 확인하지 못했다.
Netflix·쿠팡·CJ 공식 공지에는 실제 공개일 근거가 있고 RSS로 최신 공지 발견을 일부 자동화할 수 있다.
디즈니+ 한국 작품 페이지는 현재 연도만 남은 경우가 있어 검색 색인의 정확한 날짜를 그대로 수집하면 안 된다.
무료 우선 대안은 **공식 출처에서 후보 발견 → 날짜/국가/시즌/콘텐츠 종류 검토 → 승인한 후보만 기존 파이프라인에 입력**이다.
이는 제안이다. 전수 지원·수동 운영·지원 축소를 사용자가 확정한 것으로 취급하지 않는다.

시간은 한국 대상 문맥을 근거로 한 로컬 시각 후보이며 정확한 timezone을 확인하기 전 UTC instant로 만들지 않는다.
회차 날짜·완결 날짜는 읽더라도 제품 이벤트로 생성하지 않는다.

## 실제 HTTP 접근·발견 경로

인증 없는 공개 URL에 로컬 Python urllib로 최소 읽기를 수행했다. 원문 HTML/이미지/영상은 저장소에 복사하지 않았다.
[접근 메타데이터](2026-11-09-ott-access.json)에 요청 시각(UTC), HTTP 상태, 크기, SHA-256, 필요한 공개 메타데이터를 남겼다.
수집기는 구현하지 않았고 본인 키 인증 API 호출도 없었다.

| 발견 경로 | 실제 확인 결과 | 의미 |
|---|---|---|
| [Netflix 한국어 RSS](https://about.netflix.com/ko/feed.xml) | HTTP 200, RSS XML, 15개 항목. 이번 응답 2026-08-23~11-05 게시글. pubDate가 한국어 날짜 문자열 | 범용 RFC 날짜 파서만 사용하면 실패할 수 있음. RSS pubDate는 공개일이 아니며 첫 수집 때 2026 전체를 복원할 수 없음 |
| [쿠팡 뉴스룸 RSS](https://news.coupang.com/feed/) | HTTP 200, RSS XML, 12개 항목. 이번 응답 11-05~11-09 게시글 | 일반 기업/배우 소식도 섞임. 2026 전체/모든 작품/모든 수정 공지를 담지 않음 |
| [CJ RSS](https://cjnews.cj.net/feed/) | HTTP 200, RSS XML, 50개 항목. 이번 응답 10-22~11-09 게시글 | 티빙 전용 목록이 아님. 날짜/플랫폼 분류·이전 공지와의 충돌 검토 필요 |
| 한국 서비스 홈 | 웹 읽기 도구에서 TVING은 탐색 메뉴 중심, 쿠팡플레이는 지역 제한 페이지로 이동 | 이 도구/접속 환경에서 관찰한 결과다. 한국 사용자 기기에서의 불가나 해당 서비스 API 부재를 증명하지 않음 |

Netflix RSS URL은 실제 HTML의 alternate RSS 링크에서 발견했다. `/ko/news` 목록 URL은 웹 도구에서 404였다.
RSS 개수·기간은 이번 응답에서만 관찰한 값이고 계약/보장된 보관 기간이 아니다.
공지 수정 시간과 공개일을 구분하고, URL/canonical 차이·추적 쿼리 제거도 동일 출처 판별에 필요하다.
CJ 샘플에는 published_time과 modified_time이 달랐으므로 게시일 하나로 최신 근거를 판단하지 않는다.

## robots·이용 조건의 확인 범위

[Netflix robots](https://about.netflix.com/robots.txt)는 /api/ 제외를 명시했다. 공개 공지·RSS 외 숨은 API를 호출하지 않았다.
[쿠팡 뉴스룸 robots](https://news.coupang.com/robots.txt), [CJ robots](https://cjnews.cj.net/robots.txt)도 읽었다.
CJ는 검색 경로 등을 제외한다. 본 조사에서는 정해진 공지·RSS만 최소 조회했으며 사이트 전체를 크롤링하지 않았다.
[Disney+ robots](https://www.disneyplus.com/robots.txt)는 일반 User-agent에 전체 제외, 특정 검색/AI 도구에는 별도 규칙을 둔다.
초기 공개 홈 HTTP 200 확인과 범용 수집기 운영은 다르다. 일반 수집기 자동 수집 허용을 확인했다고 표현하지 않는다.
다른 봇의 User-agent로 가장하지 않는다. Disney+ 후속 상세 확인은 웹 도구로 공개 내용을 읽은 것이다.

robots에 경로가 허용되거나 페이지가 무료로 열리는 것만으로 데이터 재사용·복제/이미지 이용 허가가 입증되지 않는다.
자동 수집 주기·보관/재배포·이미지 이용에 적용할 조건은 운영 전 추가 확인이 필요하다.
공식 공지의 사실 필드와 출처 링크만 최소 보관하는 방안을 제안하며 기사 원문/포스터 재배포는 이 조사에서 결정하지 않았다.

## 통합 API 대안도 확인

- [TMDB TV watch/providers](https://developer.themoviedb.org/reference/tv-series-watch-providers)는 국가별 가용성이다.
  이 정보와 작품/시즌 일반 방영일을 합쳐 플랫폼 최초 공개일이라고 만들 수 없다.
- [JustWatch Partner API](https://apis.justwatch.com/docs/api/)는 계약 후 토큰 제공이라고 명시한다.
  한국 locale과 예정 공개일·날짜 정밀도 안내는 있지만 무료 접근·네 OTT 시즌 단위 완전 지원은 확인하지 못했다. 요청하지 않았다.
- [Watchmode](https://api.watchmode.com/), [release/leave 구분 안내](https://api.watchmode.com/use-cases/titles-leaving)는 공개일 endpoint가 유료 범위임을 명시한다.
  무료 leaving preview를 공개 예정 일정으로 오인하지 않는다. 한국/TVING/쿠팡플레이 시즌 날짜 coverage는 실제 응답 미확인이다.

## 실제 자료로 확인한 반례

1. [쿠팡 뉴스룸의 궁전랜드 캐스팅 공지](https://news.coupang.com/archives/68356/)는 제공처를 TVING으로 적는다.
   기사 도메인이 coupang이라고 플랫폼을 쿠팡플레이로 지정하면 틀린다. 2027년만 발표했으므로 정확한 날짜는 unknown이다.
2. [소년시대 시즌2 라인업](https://news.coupang.com/archives/54230/)의 2026년 상반기는 촬영 목표다.
   공개일은 추후 발표로 적혀 있으므로 2026년 공개 일정으로 대입하면 안 된다. 이 공지는 2025년 자료라 최신 상태의 확정 근거도 아니다.
3. 유미의 세포들 시즌3의 18:00은 TVING, 20:50은 tvN이다. 같은 날짜여도 방송 시각을 OTT 시각으로 복사하지 않는다.
   일본 Disney+에 공개되는 브랜드관 일정을 한국 Disney+ 일정으로 복제하지 않는다.
4. Disney+ 검색 결과의 정확한 날짜가 현재 상세 본문에는 없다. 검색 결과는 후보 발견용이며 현재 근거 검토를 대체하지 않는다.
5. [Disney+ 영국 월간 공지](https://www.disneyplus.com/en-gb/explore/articles/new-to-disney-plus-september-2026)의 날짜는 영국 시장 근거다.
   한국어 드라마라는 이유만으로 KR 날짜에 대입하지 않는다.

이는 제품에서 발생한 장애가 아니라 조사에서 확인한 입력 위험이다. 테스트 suite/독립 정확도 검사는 하지 않았다.

## 권장 구현안과 다음 완료 조건

1. 다음 작은 작업으로 Netflix/Coupang/CJ의 공개 RSS에서 링크·게시/수정 시각·내용 hash를 얻는 후보 수집을 제안한다.
   이력 채우기는 별도 공개 archive/sitemap의 허용 범위·누락을 확인해 설계한다. 하루 RSS만으로 과거를 다 채웠다고 하지 않는다.
2. 후보에 콘텐츠/시즌, 실제 플랫폼, 시장, 최초 공개 의미, 날짜 정밀도, 출처와 관찰 시각, 보류 이유를 기록한다.
   불명확한 값은 추정하지 않는다. 같은 공지의 새 버전/정정은 기존 안정 ID에 연결한다.
3. AI를 쓰면 근거 구절과 필드 후보 추출까지만 맡기고, 검토한 후보만 기존 publish 경로에 넘기는 단계를 제안한다.
   모델·API 비용·호출 방식·검토자·승인 저장 방식은 아직 정하지 않았다.
4. 위 실제 반례를 요구사항에서 독립 기대값으로 만들어 정상/오인/정정 입력 검사를 추가한 뒤 어댑터를 연결한다.
   이 문서 자체나 구현 출력을 정답으로 복사해 독립 검증 완료로 표시하지 않는다.
5. 운영 비용·완전성을 확인할 표본 실험을 한다. 예: 플랫폼별 5~10작품을 정해 출처 존재/최초 공개일/국가/시즌 확인,
   자동 추출과 사람 검토 결과 비교. 표본 수는 제안이며 아직 측정한 정확도/커버리지는 없다.

권장 결정: 부분적인 공지 기반 수집 + 검토 입력을 허용할지 먼저 정한다.
무료·완전 자동·전수 확보를 동시에 약속할 수 있는 상태는 아니다. 이번 조사로 V1 범위를 임의 축소하지 않는다.
