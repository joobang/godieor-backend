# Backend 역할과 다음 작업

공통 기준: [architecture](system/architecture.md), [plan](system/plan.md), [policies](system/policies.md).
현재 로컬 API·DB·계약과 후보 수집을 구성했고 BE-03에서 기능별 Nest 계층으로 분리했다. NestJS + PostgreSQL + Prisma와 TypeORM 제외는 확정됐다.
정확한 로컬 버전/도구는 docs/local-development.md, 현재 구조는 docs/backend-architecture.md를 따른다. 클라우드 제공자 선정은 로컬 실행의 선행 조건이 아니다.
최종 사용 형태는 iPhone + 클라우드 API/DB이고 verifier는 Mac에 둔다. 첫 목표는 Mac API/DB와 앱의 연결이다.

제품 코드가 기대값을 스스로 승인하지 않는다. API 계약은 소비자 관점과 독립 검토를 거친다.
제공처 가용성 정보만으로 플랫폼별 한국 공개 날짜를 추정하지 않는다.
자체 검사는 정규화/저장/API를 담당하고, 별도 verifier는 고정 두 SHA의 실제 통합 흐름을 관찰한다.

## 일정 범위·갱신 작업

4개 OTT, 게임 정식 출시, 2026-01-01 이후 알려진 미래 전체, 하루 1회 정상 갱신을 반영한다.
기간/페이지 조회·초기 이력 수집·일 1회 갱신·수집 결과와 마지막 성공 시각을 설계한다.
한국/KST 기본 + 국가·시간대 선택, PC·PlayStation·Xbox·Nintendo Switch, 실패 시 마지막 데이터/성공 시각을 계약에 반영한다.
[범위 결정 ADR](decisions/005-content-range-refresh.md)을 참고한다.

## 계정 로그인 작업 제안

계정 기반 + Google 로그인 방향을 반영한다. Google ID token 검증·내부 계정·서비스 세션을 API 계약에 포함한다.
Google 로그인한 사용자의 이용, 개인 설정·찜의 계정별 서버 저장/복원은 확정했다.
세션 수명·갱신/폐기·동기화 충돌은 후속 설계 항목이다.
실제 OAuth 설정·실기기 로그인과 가상 인증 fixture 검사를 구분한다.
구체 설계 제안은 [ADR-004](decisions/004-google-account.md)를 참고한다.

## 기술 기록

선택 이유·제약·대안·되돌릴 조건은 이 저장소 ADR에 남긴다.
학습/면접/블로그용 서술은 verifier/docs/learning 카탈로그에 LEARN-ID로 연결하고 실제 실행 근거를 참조한다.
개발 중 실패를 운영 장애 경험으로, 가상 자료를 실제 연동 성과로 바꾸지 않는다.

## 월간 캘린더·통일한 찜 동작 후속

극장 영화 개봉일·EPL 경기 포함, 신규 기본 영화·OTT/설정에서 게임·EPL 추가, 작품·일정 찜 모두 지원을 반영한다.
공통 설계의 화면/찜 후속 항목과 app/docs/design/calendar-first.md, backend ADR-006에 따라 소유 범위를 구현/독립 검토한다.

OTT는 최초 공개일만 제공한다. 회차별 공개/완결은 제외하며 시즌별 최초 공개 포함은 후속 추천안 수락으로 확정했다. 메인은 선택한 캘린더 중심안이다.

로그인 전 공개 일정 조회, Google 로그인 후 찜·설정 저장, V1 알림 제외를 로컬 구현 계약/검사 초안에 반영한다.
