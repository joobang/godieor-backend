# ADR-010 · 공지 후보와 제품 일정을 나누고 정확한 날짜를 검토한다

상태: 사용자 날짜 정책 확정 / 로컬 구현 선택. 2026-11-09. DATA-02A / LEARN-0008.

사용자가 연·월·일 있는 일정만 반영하고 연/월만 있는 자료는 후보로 보류하는 제안을 수락했다.
자료 발행일, 촬영 목표, TV 방송일을 OTT 최초 공개일로 오인할 실제 위험은 DATA-01에서 관찰했다.

RSS 링크 발견을 TypeScript 보조 CLI로 만들고 공지 후보는 Git 제외 로컬 JSON에 보관한다.
새 DB/공개 API 없이 작은 단위로 검토 흐름을 실행하기 위해서다. 제품 영속 DB는 PostgreSQL이며 이를 대체하지 않는다.
fast-xml-parser 5.12.0을 고정해 XML 구조를 읽고 원문은 보관하지 않는다. 날짜/시장/플랫폼/드라마/최초 공개 근거가 확인된 후보만 내보낸다.
시각/시즌 null을 허용하고 없는 날짜는 생성하지 않는다. 공지 revision이 바뀌면 이전 검토를 해제한다.

대안: RSS 날짜/도메인에서 자동 확정(의미가 달라 배제), 즉시 제품 DB 스키마 확장(검토 흐름을 먼저 확인),
별도 수집 서버/유료 데이터셋(무료·로컬 우선 요구 및 실제 coverage 미확인), AI 자동 확정(근거 검토를 대체하지 못함).

한계: 로컬 파일 lock은 OS 격리·사용자 인증·완전한 crash 내구성을 보장하지 않는다.
한 공지 여러 작품, 복수 공지 같은 작품, 안정 작품/시즌 식별, 제품 publish·수정 동기화는 아직 후속이다.
병렬 작업/원격 운영이 필요해지면 PostgreSQL 후보 테이블과 migration·검토 권한을 별도 설계한다.
공식 출처 robots/이용 조건은 운영 시 다시 확인한다. public page 접근이 재사용 허가 전체를 뜻하지 않는다.

공식 기술 근거: [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser),
[Node globals/fetch](https://nodejs.org/docs/latest-v24.x/api/globals.html).
구현 선택·정책 승인은 자체 기록이며 외부 라이브러리가 제품 정확도를 보장하지 않는다.
