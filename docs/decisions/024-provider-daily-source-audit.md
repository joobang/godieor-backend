# ADR-024 · 제공처별 일일 실행·실패 복구와 원천 ID 감사

상태: 구현 결정 기록, DATA74/PROD005~009. 자동 데이터 수집·로컬 운영 설정 범위이며 외부 승인이나 배포 선택을 새로 확정하지 않는다. ADR023/LEARN0006과 연결한다.

영화·EPL·게임을 단일 CLI 호출만으로 운영하면 시작 단계 실패가 모든 원천을 막거나 실행 결과/마지막 성공이 사라질 수 있다.08:30 KST LaunchAgent에 제공처별 독립 자식 프로세스를 순차 실행하는 runner를 연결했다. 기존 OTT09시 job과 별도 label·잠금을 쓴다. Node24 고정 경로와 backend .env 로딩을 유지하며 비밀을 plist/임의 자식 출력에 복사하지 않는다.

당일 성공한 scope는 skip하고, 실패 뒤의 재실행은 같은 날 앞선 성공이 있어도 다시 시도한다. 전체 정상 job의 마지막 성공 보고서는 실패·중단 시 보존한다. job 시각/skip과 실제 원천 수집 시각을 구분하고 후자는 DB/API freshness를 따른다. 제공처별 timeout·signal 시 process group을 종료하고 잠금을 해제한다. 파일 결과는 원자적으로 교체하며 비정상 출력·잠금 충돌을 성공으로 해석하지 않는다. 원격 운영과 달리 로그인된 Mac/실제 DB 가용성이 필요하다.

IGDB49 release ID는 제목 재검색 대신 기존 content_source.game ID로 games/release_dates 관계와 플랫폼·지역을 다시 조회했다.29게임을 모두 찾고 기존5 ID도 현재 존재함을 확인했다.37 날짜 후보/4 부분·미정 후보/3 복수·부재/5 현재 비본편으로 분류했다. 원래 release_region 숫자가 저장되지 않았고 새 후보38개가 다른 공용 event ID로 이미 저장돼 있어, 자동 재결속이 지역별 이벤트/찜/공용 ID를 훼손할 수 있다. 이 감사는 데이터/ID를 변경하지 않는다. 현재 분류를 과거 game_type의 변경이 확정된 것으로 말하거나, 후보를 모두 같은 이벤트라고 승인하지 않는다.

후속은 원천 지역 provenance 보존과 source/event ID alias·중복 공개 이벤트의 참조 보존이다. 원래 지역이 없는 이벤트는 단순 제목·게임/플랫폼 일치로 병합하지 않는다. 날짜 정밀도·공식 지역·공용 ID와 찜에 대한 계약 검토 및 실제 DB 검사가 필요하다. 기존49건의 잘못된 날짜·분류가 해결됐다고 선언하지 않는다.

실제 LaunchAgent 명시 기동/당일skip, KOBIS 자식에만 접근 불가 loopback DB를 주입한 제어 실패와 다른 제공처 계속 실행·마지막 성공 보존, 정상9범위 재수집/게임새10/기존32683행·이력 보존을 관측했다. 다음 자연08:30 기동은 미관측이다. 테스트·고정digest 일회용DB와 실제 API 결과는 DATA74 증거를 따른다. 스케줄/환경·출력 계약·실패 상태/원천 관계와 identity 정책 변경 시 재검토한다.
