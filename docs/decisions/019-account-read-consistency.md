# ADR-019 · 계정 설정·찜의 읽기 일관성

- 2026-11-13, BE-AUTH-07, PROD-003/006/010. 구현 결정, 독립 승인 대기. LEARN-0019.

찜 목록의 콘텐츠·이벤트·버전은 하나의 응답이다. 여러 연결의 Promise.all로 읽으면 다른 기기의 원자적 저장 전후 값이 섞일 수 있다. 설정도 본문·관계 목록을 같은 시점으로 읽어야 한다. 읽기 전용 RepeatableRead 트랜잭션을 사용하며 찜 조회는 같은 연결에서 순차 실행한다.

설정 저장 후 트랜잭션 밖의 재조회는 다음 기기의 저장을 현재 저장 응답으로 반환할 수 있다. 저장 트랜잭션 안에서 결과를 읽어 반환하고 버전 충돌은 기존409정책을 유지한다. API 모양·DB 스키마는 바꾸지 않는다.

scripts/check-account-snapshot-db.cjs는 실제 임시 PostgreSQL에 두 연결을 사용한다. 읽기 중 다른 기기의 쓰기, 쓰기 commit 직후 다음 기기의 쓰기를 결정적인 위치에 주입한다. 이전703a8e1 코드 두 케이스 실패·수정 코드 두 케이스 성공을 관측했다. 다른 계정 불변도 검사했다. 실제 사용자 장애나 폰 실험이 아니며 성능 개선 수치는 측정하지 않았다.

읽기 트랜잭션은 응답당 짧게 유지한다. 새 페이지 조회 사이의 변경은 기존 favoritesVersion/cursor 충돌 정책으로 감지한다. 트랜잭션 일관성은 실제 Google 로그인·iOS 지연 응답 처리·기기간 전체 흐름 검증을 대신하지 않는다.
