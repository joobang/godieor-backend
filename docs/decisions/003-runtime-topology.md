# ADR-003 · 최종 실행 위치와 로컬 우선 개발

- 날짜: 2026-11-09 KST
- 상태: **사용자 확정: 실행 위치와 단계**. 제공자·정확한 버전·설치/배포 수단은 미정.
- 실제 사용자 답변: “좋아 우리가 구성한대로 최종 구성형태로 이렇게하자. 일단 로컬 실행을 목표로가보자.”
- 정책 연결: P02, P10 실행 위치, P12 진행 단계. P03 로그인·동기화는 아직 결정 전이다.

## 최종 형태

본인 iPhone 앱이 Wi-Fi/LTE·5G로 클라우드 NestJS API를 호출하고, 서버는 Prisma로 클라우드 PostgreSQL에 접근한다.
verifier는 Mac에서 필요할 때 실행한다. 앱·verifier를 상시 클라우드 서비스로 배포하는 구성이 아니다.
GitHub의 세 소스 저장소와 실제 서비스 실행 위치를 구분한다.

## 로컬 첫 목표

Mac PostgreSQL → Prisma migration/저장·재조회 → NestJS API → Simulator/본인 iPhone에서 응답 확인.
처음 fixture를 사용하면 가상 자료임을 명시한다. 실제 제공처 연동은 후속 작업이다.
클라우드 제공자 선정을 기다리지 않고 로컬부터 구현한다. 정확한 버전/DB 도구는 호환성을 확인해 선택한다.
로컬 개발에 사용하는 DB와 독립 검사 DB를 구분한다. 운영 DB를 테스트에 사용하지 않는다.

## 선택 이유와 남은 정책

개발 초기 비용을 줄이면서, 최종적으로 Mac을 켜두지 않아도 외부에서 일정을 볼 수 있는 목표를 유지한다.
개발 환경 주소·비밀·연결 설정을 운영 환경과 분리하고 동일 API 계약과 versioned migrations를 사용한다.
클라우드 무료 조건, 제공처 접근·이용 조건, 실제 키, iPhone 설치 방식, 캐시 보관 정책은 아직 확정하지 않았다.
이 문서 갱신으로 로컬 실행이나 클라우드 배포가 완료된 것은 아니다.
