# ADR-006 · 통일한 찜 동작과 작품/일정 식별자 분리

- 날짜: 2026-11-09 KST. 상태: 사용자 방향 확정, 저장 모델/해제 의미는 구현 전 제안.
- 연결: P03/P07, PROD-004~006. 원본 UI 근거는 app/docs/design/calendar-first.md.

사용자는 작품·개별 일정 모두 찜하고 경기 하나와 작품 하나를 같은 수준에서 다루길 원했다.
UI는 관심 대상을 저장하는 동작으로 통일하고 내부의 콘텐츠와 이벤트는 분리한다.
EPL 경기는 Event를 직접 참조하며 찜을 위해 가짜 작품을 만들지 않는다.

## 대안과 선택 제안

- `target_type + target_id` 한 테이블은 간단하지만 보통 FK만으로 대상 존재를 보장하기 어렵다.
- 공통 SavedTarget 상위 엔티티는 FK 통합이 가능하지만 초기 모델과 삭제/수명 관리가 복잡해진다.
- 초기 제안은 ContentFavorite(user_id, content_id)와 EventFavorite(user_id, event_id)의 명시적 FK/유일성이다.
  사용자 API/화면은 한 저장 목록으로 합친다. Prisma schema와 실제 제약은 아직 작성하지 않았다.

찜 목록은 직접 저장한 Event와 찜 Content의 관련 Event를 합치고 안정 이벤트 ID로 중복 제거한다.
작품 찜을 매 회차 행으로 복제하지 않아 신규 회차도 포함한다. 작품 해제는 직접 Event 찜을 지우지 않는다.
직접 Event 해제 후 작품 찜에 포함되어 남는 상태를 UI가 설명해야 한다.
일정 연기·변경은 같은 ID를 갱신하고 관계를 유지한다. 지역/플랫폼/기기 범위는 계정 설정과 조회 계약을 따른다.

## 이번 확정 데이터 범위와 설정

극장 영화 개봉일과 EPL 경기 일정은 포함한다. 극장별 상영 회차/좌석·팀 구독은 포함하지 않는다.
신규 기본 표시 분야는 영화·OTT. 게임/EPL 숨김은 수집 중단이나 찜 삭제가 아니다.
계정별 분야 설정 복원과 임시 필터를 분리한다. 빈 필터는 활성 분야 전체다.
모두 OFF이면 분야 추가 안내이며 자동으로 전체 분야 조회로 확대하지 않는다.

## 후속 검사 제안

다른 사용자 FK 접근 차단, 같은 찜 재요청의 중복 방지, 양쪽 찜 합집합 중복 제거,
작품 해제 후 직접 일정 보존, 직접 일정 해제 후 상속 상태, 신규 회차 포함, 날짜 변경의 연결 유지,
신규 기본값/기존 설정 복원/숨김 후 찜 보존을 독립 기대값으로 검사한다.
이 문서로 실행 검사나 acceptance 승인을 주장하지 않는다.
