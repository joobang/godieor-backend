# DATA-88 · 상업영화 달력 정리 및 IGDB WORLD 게시 복구

- 요구 PROD-005/009, GD-005/009. 사용자 요청은 극장 개봉 상업 장편영화만 달력에 표시하고 기존 과다 등록 항목은 정리하는 것이다. 독립·예술·다큐·단편 영화는 제외한다. IGDB WORLD 백필의 대용량 게시 실패도 수정한다.
- 기준 backend dev d0d3648. 구현 브랜치 codex/commercial-movies-world-20261119. 앱 및 verifier 변경 없음.
- 예상 실패는 KOBIS 영화목록의 제작/배급사 혼동, 조회 실패 후 과도한 숨김, 기존 즐겨찾기와 ID 손실, IGDB P2028 트랜잭션 제한, 실패 뒤 재실행의 중복 게시다.
- KOBIS 공식 상세의 배급 참여와 지정된 주요 상업 배급사, 장편 및 장르를 확인한다. 기준에 맞지 않는 기존 KOBIS 이벤트는 is_listed=false로 보존한다. 기존 상세·즐겨찾기·출처·변경 이력은 유지한다. 정책은 주요 배급사 기반의 보수적 휴리스틱이며 전국 극장 상영 여부에 대한 완전한 증명은 아니다.
- IGDB WORLD 게시를 최대 100건씩 독립 트랜잭션으로 나눠 완료 상태를 마지막에 확정한다. 재시도는 안정된 provider source ID로 같은 이벤트를 재사용한다. 대량 실패 후 이전 청크가 먼저 게시될 수 있으며 전체 범위 원자성은 변경된다.
- 데이터 마이그레이션은 GitHub Actions 수집 전에 적용한다. 수집 전 DB를 직접 DELETE 하지 않는다. 성공한 KOBIS 수집에서만 이전 이벤트 달력 노출을 조정한다.
- 실행 대상은 GitHub Actions `main / backfill / kobis` 다음 `main / backfill / igdb-world`의 두 개 독립 선택이다. `all` 백필은 사용하지 않는다. 실제 적용과 결과 건수는 해당 Actions 실행 및 운영 DB 확인 후 기록한다.
- 관련 학습은 LEARN-0022, KOBIS 수집·이벤트 식별은 LEARN-0006이다. 동작 확인은 빌드, provider 및 게시 회귀 테스트, 전체 테스트, 원격 CI, 운영 백필 순서로 진행한다.
