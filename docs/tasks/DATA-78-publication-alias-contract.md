# DATA-78 · IGDB 게시 검토·alias 호환 계약 초안 (2026-11-17)

- 요구 ID: PROD-005/006/007/009, GD-005/006/007/009. 근거: DATA-77 실 DB 감사 49건, 불일치 0, 관련 찜 0, 다른 공개 ID 중복 가능 38, 과거 숫자 지역 NULL 49. 상태: **설계·독립 검증 제안, 미승인/미구현**.
- 변경 범위: 공개·검토 상태 의미, ID 호환 계약, 데이터 교정 제약, 독립 검증 사례. 이 카드로 실제 게시·마이그레이션·API 변경을 승인하지 않는다.
- 예상 실패: 동일 게임 ID만 보고 지역/플랫폼이 다른 출시를 병합; 기존 `event.id` 상세 404; 사용자가 찜한 공개 ID가 교정 후 사라짐; 미정 일정을 자정 UTC로 표시; 신규 숫자 지역을 과거 NULL에 소급 전파; 일시적 원천 실패를 취소로 표시.

## 사용자에게 보일 동작 제안

1. 출시 상태 `event.status`는 실제 일정의 상태이며 검토 큐의 `hold`로 덮어쓰지 않는다. 검토 상태는 원천별로 별도 저장·이력 기록하고 일정 표시 여부는 제품 계약에서 명시한다.
2. 이미 공개된 이벤트의 원래 `event.id`는 안정적 링크다. 비공개 검토 상태로 옮기더라도 상세 접근은 명시적 상태와 이유를 반환하고 찜 관계는 유지한다. 조회 실패/일시적 원천 장애만으로 404·삭제/취소하지 않는다.
3. 별칭은 자동 생성하지 않는다. 원본 release ID, 후보 release ID, 게임 정체성, 플랫폼, 정수 지역, 날짜/precision, 공식 근거 URL, 검사 시각을 묶은 수동 검토 기록에 승인 근거가 있어야 한다. 과거 `source_release_region=NULL`은 근거 부족으로 취급한다.
4. 교정 시 과거 공개 ID와 즐겨찾기 접근을 보존하는 API 리다이렉션/별칭 해석 계약, 이중 게시 방지 규칙, 취소·복구 정책을 먼저 확정한다. 기존 데이터 대량 수정 전에 격리 DB로 교정과 역교정 검증이 필요하다.
