## 구현 및 실측

- 검토한 TMDB 별칭 16개를 `data/curated/ott-poster-tmdb-identities-2026-11-19.json`에 결속했다. 동적 타이틀 검색보다 우선해 신원확인된 ID를 조회하며 TMDB 상세 제목까지 대조한다. 기존 공개 날짜·원천·찜과 이미 채워진 포스터는 유지한다.
- 로컬 PostgreSQL의 실 OTT 이벤트(가상 데이터 제외) 116건 중 1차 포스터90건(77.6%)에서 **106건(91.4%)**으로 증가했다. 빈 포스터는 26→10건. TMDB 매핑은 91→107 이벤트. 이전 2차 적용 첫 실행에서 데이터는 반영됐지만 이후 미확보 보고 SQL의 SELECT DISTINCT ORDER BY 표현 차이로 42P10 오류가 발생하여 정렬을 열 번호 기준으로 수정했다. 재실행 결과 `postersUpdated=0`, `identitiesSaved=0`, `lookupFailures=0`으로 재실행 안정성 확인.
- 남은 10건은 Día de Muertos: Ofrenda, 가금채, 그 아이, 네이트 바가치: 이 정도면 잘했지, 마지막 주문을 받습니다, 미키의 나 홀로 집에, 샐리시의 12가지 크리스마스 게임, 스마일 클리닉, 심장소리, 제 아들을 대신하여. 샐리시 작품은 TMDB ID 341600이 있으나 포스터가 제공되지 않아 대기한다. 나머지는 확인되지 않은 동일 작품 식별자를 임의 지정하지 않는다.
- 결과 보고서 `work/ott-posters/latest.json`에 제공처/원천별 분모, TMDB 저장 건수, 이미지 누락과 사유를 기록한다. 통계는 전체 이벤트 기준이며 콘텐츠 UUID 단위 DB UPDATE 개수와 다를 수 있다.
